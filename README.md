# Label-Prior Leakage in Personalised Federated Learning Evaluation

Code for a study of how personalised federated learning is benchmarked, with a
gastrointestinal endoscopic screening case study.

Personalised FL is commonly evaluated by partitioning **both** the training and
the test set with one Dirichlet proportion matrix, then scoring each client's
model on its own test shard. This repository implements a diagnostic for the
label-prior leakage that introduces, a leak-free alternative protocol, and the
full benchmark under both.

Code only — every table, figure and checkpoint is regenerated by running the
pipeline.

## Running

Stages are ordered; each depends on the one before it.

```bash
python scripts/01_run_data_preprocessing.py
python scripts/02_run_feature_caching.py  
python scripts/03_run_federated_training.py
python scripts/04_run_inference_evaluation.py
python scripts/05_run_xai_generation.py 
python scripts/06_aggregate_and_plot.py 
python scripts/07_run_protocol_leak_analysis.py
```

| Stage | Produces |
|---|---|
| 01 | Deduplication, label-conflict detection, PHI redaction, curated manifest |
| 02 | Frozen 1792-d feature bank (ResNet-18 + EfficientNet-B0) |
| 03 | 7 methods x 5 seeds x 4 Dirichlet alpha = 140 federated runs |
| 04 | Inference-management evaluation, ablation, privacy / drift / coverage sweeps |
| 05 | Grad-CAM++ attributions, expected calibration error, reliability curves |
| 06 | Multi-seed aggregation, DeLong and Wilcoxon tests, publication figures |
| 07 | Dual-protocol leakage analysis |

Timings are wall clock on an Intel i7-1355U (10 cores, 16 GB RAM, no GPU).

To reproduce only the leakage analysis: stages 01 → 03 → 07. The Dirichlet
sweep inside stage 07 needs no training at all.

## Implementation notes

**Evaluation protocol.** Only the training set is sharded across clients. The
held-out test set stays pooled, and personalised models are routed to it by a
feature-space nearest-centroid router that never sees a label or a ground-truth
client id. `prior_only_auc()` in `scripts/07_run_protocol_leak_analysis.py` is
the diagnostic: a predictor that reads no pixels and knows only each client's
training base rate. Under a leak-free protocol it must sit at chance.

**Curation.** Perceptual-hash deduplication, cross-class label-conflict
detection, and stratified group-aware splitting — near-duplicate groups are
assigned wholly to one split, so no near-copy of a training frame appears in
test.

**PHI redaction.** Endoscopic frames can carry a burned-in acquisition banner.
Because the banner sits at fixed coordinates within an acquisition geometry, it
has near-zero variance across frames while mucosa varies. Stage 01 derives a
per-resolution crop box as the largest rectangle inscribed in the high-variance
region, so the banner cannot lie inside it.

**Parameter-efficient federation.** Encoders are frozen and features cached
once; only a ~0.5 M-parameter adapter head is federated. This is what makes 140
runs tractable on a CPU, and it narrows the gap between methods relative to
end-to-end fine-tuning.

**Statistics.** DeLong on pooled per-sample predictions is the primary
inferential test. Wilcoxon signed-rank across seeds is reported for
completeness; with 5 seeds the smallest attainable two-sided p-value is 0.0625.

**Reproducibility.** Seeds {42, 123, 456, 789, 2024} are set for Python, NumPy
and PyTorch. Encoders are frozen and pretrained, so the feature bank is
deterministic.
